Local-first point of sale

Why the register records the work before it reports success—and why offline continuity still has boundaries.

The failure mode

A store cannot wait for the network to decide whether the sale happened.

An online-first register makes the cashier’s success depend on a cloud mutation: send the command, wait for acceptance, then update the interface. That arrangement looks simple until connectivity becomes slow, intermittent, or falsely reports itself as available.

The operational problem is deeper than a loading spinner. If the browser and the backend disagree at the wrong moment, the cashier can lose stable receipt context, repeat a command, or become uncertain whether a customer has already paid. An offline fallback added beside that path creates a second version of the register with different guarantees.

The command boundary

Local evidence exists before cashier success.

On a provisioned, locally authorized register, Athena appends the cashier event to the durable local record before returning success. Opening a drawer, changing a cart, recording payment, completing a transaction, and closing out all begin at the same local command boundary, regardless of whether the browser appears online.

Connected and disconnected

One operating path, not an offline fallback.

The same append-first command path runs when the network is healthy and when it is unavailable. Connectivity can wake synchronization, refresh seed data, and validate cloud state; it does not decide whether the cashier’s action is first recorded locally.

This keeps the active cart, payment state, receipt context, and register lifecycle recoverable from one event history.

Cloud acceptance

Synchronize in order. Reconcile without rewriting history.

When connectivity and cloud validation are available, Athena uploads eligible events in order through an authenticated terminal boundary. The upload is idempotent: retrying the same local evidence does not create a second sale, and accepted mappings connect local identifiers to their cloud records.

Acceptance is not the only possible outcome. A stale product reference, changed authority, or conflicting cloud state can require review. In that case Athena preserves the completed local sale, records the reconciliation posture, and directs the conflict into manager-visible work instead of rewriting the cashier’s receipt or pretending the mismatch never happened.

Two authorities

Local continuity and cloud truth do different jobs.

The register is authoritative for whether it durably recorded the cashier’s action. After upload is accepted, the cloud projection becomes authoritative for Athena’s shared cloud record. Keeping those responsibilities explicit lets the store continue locally without treating an unvalidated device as universally trusted.

Local authority

Protect the cashier’s completed timeline

  • Requires terminal, staff, drawer, and durable-storage readiness.
  • Accepts the command into the local event log before success.
  • Preserves cart, payment, transaction, and receipt continuity.

Cloud authority

Project the shared business record

  • Authenticates and validates uploaded terminal events.
  • Maps local identifiers and applies accepted business records.
  • Surfaces conflicts and reconciliation work without erasing local evidence.

Candid limits

Offline-first is a bounded promise.

POS is Athena’s offline-first workflow; the rest of the operating system should not be described as universally available without a connection. Even at the register, offline continuity depends on a provisioned terminal, a locally authorized staff member, drawer authority, and a healthy durable local destination.

  • Last-known stock can drift. A disconnected register can preserve a sale, but it cannot prove another terminal or channel has not changed inventory.
  • Cloud validation can wait without disappearing. Deferred events remain visible to synchronization and support flows until validation returns.
  • Conflict is evidence, not failure theater. Review work remains explicit rather than being hidden behind an apparently successful sync.
  • Accepted cloud projection becomes the cloud source of truth. Local continuity does not grant a terminal authority over every shared business record.
